# Update Log — 2026-03-03

## Tổng quan

Triển khai hệ thống phân quyền hai lớp (Permission + UI Function) kết hợp CMS-driven UI rendering cho màn hình Manager Approvals Detail.

---

## Kiến trúc phân quyền

```
permissions (string[])     →  kiểm tra cấp trang (page-level guard)
                               vd: EXPENSE_APPROVE, EXPENSE_REJECT
                               → frontend redirect /not-found nếu thiếu

functions (number[])       →  kiểm tra cấp phần tử UI (element-level)
                               vd: function_id=1 (EXPENSE_ACCEPT), id=2 (EXPENSE_REJECT)
                               → CMS ẩn button/form nếu user không có
```

### CSV Patch format

Admin có thể import CSV để patch CMS JSON mà không cần replace toàn bộ:

```csv
# nodeId,propertyPath,newValue
btn-accept,label_key,manager.btn.approve_now
btn-reject,variant,warning
```

Logic: DFS tìm node theo `id` → set nested property → save as new version → deactivate old version.

## Luồng dữ liệu hoàn chỉnh

```
Login / Session refresh
  └─ BFF Promise.all([fetchUserProfile, fetchUserPermissions, fetchUserFunctions])
       └─ UISession { permissions: string[], functions: number[] }
            └─ Frontend AuthContext
                 ├─ hasPermission("EXPENSE_APPROVE") → guard trang /manager/approvals
                 └─ hasFunctionId(1) / hasFunctionId(2) → CMS ẩn/hiện button

Vào /manager/approvals/:id
  ├─ useGetScreenConfigQuery("manager.approvals.detail")
  │    └─ BFF /scr-001/manager.approvals.detail → Java /api/v1/screen-configs/{key}
  │         └─ screen_configs DB → config_json (active version)
  ├─ Zod safeParse(rawConfig)
  │    ├─ success → CmsNode render tree
  │    └─ fail    → StaticFallback layout
  └─ RenderContext:
       ├─ hasFunctionId → ẩn node nếu user không có function
       ├─ expense       → display.field data_key → camelCase mapping
       ├─ actionHandlers→ EXPENSE_ACCEPT / EXPENSE_REJECT / EXPENSE_REJECT_SUBMIT
       ├─ formValues    → controlled textarea (txt-reason)
       ├─ activeFormId  → "reject-form" | null (toggle action-bar ↔ reject-form)
       └─ t(label_key)  → i18n en/vi/de tự động theo ngôn ngữ user
```

## i18n trong CMS

`label_key` trong CMS JSON là i18n key thông thường. Không cần thay đổi cấu hình i18n:

| label_key | en | vi | de |
|-----------|----|----|-----|
| `manager.btn.accept` | Approve | Phê duyệt | Genehmigen |
| `manager.btn.reject` | Reject | Từ chối | Ablehnen |
| `manager.btn.confirm_reject` | Confirm Rejection | Xác nhận từ chối | Ablehnung bestätigen |
| `manager.rejection_reason` | Rejection Reason | Lý do từ chối | Ablehnungsgrund |
