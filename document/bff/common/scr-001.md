# SCR-001 — GET /scr-001/:screenKey

## Process Flow

```
Frontend (RTK Query useGetScreenConfigQuery) gọi GET /api/scr-001/:screenKey
  → BFF lấy idToken từ HttpOnly cookie
  → Forward đến Java Backend: GET /api/v1/screen-configs/:screenKey (Bearer idToken)
  → Backend trả raw config_json string
  → BFF: nếu response.data là string → JSON.parse() → trả JSON object
  → Frontend: Zod safeParse → CmsNode tree hoặc StaticFallback
```

---

## BFF Endpoint

- **Method**: GET
- **Path**: `/api/scr-001/:screenKey`
- **Auth**: HttpOnly cookies (idToken required)

---

## Input (Path Params)

| Field | Required | Type | Ghi chú |
|-------|----------|------|---------|
| screenKey | ✅ | string | URL-encoded. Ví dụ: `manager.approvals.detail` |

---

## Backend API Gọi

| Method | URL | Auth |
|--------|-----|------|

---

## Ghi chú

- BFF parse JSON string → object để frontend không cần double-parse
- Nếu Backend trả lỗi (404, 500) → BFF propagate status code
- Frontend luôn có StaticFallback — nếu API fail hoặc Zod parse fail, trang không bị broken
